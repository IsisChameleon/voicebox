voicebox · Stage 2 — the event stream

Whisper hears only the app bot (the agent under test); our tester voice is Kokoro TTS. A read-only observer turns pipeline frames into a monotonic, timestamped event log; listen(cursor) streams it to Claude a window at a time. Replaying a real EmberTales call.

app_bot — agent under test tester — our synthetic user app_bot_transcript — the payload meta / listen + cursor

The cursor is an index, not a clock

listen(timeout, cursor) returns every event past cursor plus the next cursor, blocking only until something new exists. Pass it back to resume — nothing missed, nothing re-read. cursor=0 replays the whole call. This is what kills the one-turn lag.

The names are inverted on purpose

pipecat’s “user” is the app bot (its audio is our input) and pipecat’s “bot” is our tester (our TTS is the output). The observer is the single place that mapping lives, so the event stream reads in the test’s terms.

What the log reveals: overlap

At t+27.84 the tester started talking while the app bot was still speaking (started t+23.78, stopped later) — real talk-over. The old string-only listen could never have shown this; the timestamped stream makes it obvious.
